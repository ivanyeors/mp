# 02 — Service fees in Costings: table, reader, *Costings → Service fees* page, complimentary rule

**Type:** AFK
**Blocked by:** 01
**User stories:** 1, 2, 3
**Labels:** `enhancement`, `needs-triage`, `P1`, `area:costings`

## Goal

An operator opens **Admin Panel → Inventory → Costings → Service fees**, changes Measurement (Premium) from $50 to $55, saves, reloads, and sees $55. The change is in the Audit Log. Nothing charges yet: this slice is additive and inert, and everything downstream reads what it stores.

## Scope

### Migration — `supabase/migrations/<ts>_service_prices.sql`

```sql
create table if not exists service_prices (
  key text primary key
    check (key in ('measurement_premium', 'measurement_basic', 'readjustment')),
  msrp numeric(12,2) not null check (msrp >= 0),
  cost_price numeric(12,2) null check (cost_price is null or cost_price >= 0),
  currency text not null default 'SGD',
  updated_at timestamptz not null default now()
);
alter table service_prices enable row level security;   -- no policies: server reads only

insert into service_prices (key, msrp) values
  ('measurement_premium', 50.00),
  ('measurement_basic',   30.00),
  ('readjustment',        30.00)
on conflict (key) do nothing;

insert into site_settings (key, value) values
  ('readjustment_free_visits', '1'),
  ('readjustment_free_window_days', '60')
on conflict (key) do nothing;
```

- `msrp` is **not null**. A service with no price would mean "free" in one reader and "unpriced, refuse" in another. `priceComposedBuild` already refuses a null-MSRP add-on rather than charging zero (`lib/pricing/composed-price.ts:113-116`). Here the database makes the question impossible instead.
- The keys are a closed CHECK set. Each one is wired to a rule in code (slices 03 and 06).

### Reader — `lib/pricing/service-prices.ts`

```ts
export type ServiceKey = "measurement_premium" | "measurement_basic" | "readjustment";
export type ServicePrices = Record<ServiceKey, { msrp: number; currency: string }>;
export async function loadServicePrices(admin: SupabaseClient): Promise<ServicePrices>;
export type ReadjustmentPolicy = { freeVisits: number; freeWindowDays: number };
export async function loadReadjustmentPolicy(admin: SupabaseClient): Promise<ReadjustmentPolicy>;
```

- `loadServicePrices` throws if any of the three rows is missing. A missing row is a broken deploy, not a free service.
- `loadReadjustmentPolicy` parses the two `site_settings` keys to non-negative integers, falling back to 1 and 60 on garbage, the same as `parseAppointmentSettings`.
- Add `lib/pricing/service-prices.ts` to the `pricing-surface.check.ts` allowlist as the **only** reader of `service_prices` (mirroring the `product_prices` rule at `:47-63`).

### Page — `app/[lang]/settings/costings/services/page.tsx`

- **Guard:** server component, `requireAdminPage("costings")`. The parent Costings page relies on the sidebar redirect; this one guards itself.
- **Layout:** three rows (label, MSRP, cost, "Charged when…" help text, as in the PRD's *Design* block), then the **Complimentary re-adjustment — Premium Mpillow only** fieldset with the two integers.
- **Saving:** one **Save** for the whole page, with the same dirty-state and toast pattern as Costings.

### Save — extend `app/[lang]/settings/costings/save/route.ts`

- Add an optional `services: { key: ServiceKey; msrpCents: number; costCents: number | null }[]` and an optional `readjustmentPolicy: { freeVisits: int 0..10; freeWindowDays: int 0..365 }` to `PayloadSchema` (`:83-92`). The route stays the single Costings write surface.
- Upsert `service_prices`. Upsert the two `site_settings` keys and `invalidateTag("site-settings")`, as the appointments route does (`app/api/settings/appointments/route.ts:148`).
- `recordAdminAction` with a before/after for each changed key.
- **Do not** call `syncAllAutoGeneratedProductPrices()` or `reResolveShopifyLineCosts()` (`:300-308`) for a services-only save. No storefront variant reads `service_prices`, and service prices never go to Shopify (PRD decision (k)).

### Sidebar and cross-links

- **Sidebar:** in `NAV_GROUPS` (`components/settings/settings-sidebar-nav.tsx:95`), give **Costings** a child, `{ href: "/settings/costings/services", label: "Service fees", tooltip: "Measurement and re-adjustment fees", Icon: HandCoins }`, following the **Products → Configure** pattern.
  - Verify `permissionForHref` resolves the child to `costings`, so roles that can see Costings see it and others are redirected (`:322-331`).
- **Appointments settings sheet** (`components/settings/appointments-settings-sheet.tsx:437-467`): in the re-adjustment section, show the current fee and rule read-only (*"$30 per re-adjustment · 1 free visit within 60 days for Premium Mpillow"*), with an *"Edit in Costings → Service fees"* link.

## Acceptance criteria

- [ ] The migration applies cleanly with `supabase db push` and seeds 50 / 30 / 30 and 1 / 60.
- [ ] `loadServicePrices` returns all three. It throws, rather than returning zero, when a row is deleted.
- [ ] `pricing-surface.check.ts` fails when any file other than `lib/pricing/service-prices.ts` selects from `service_prices`.
- [ ] *Service fees* appears under **Costings** in the sidebar for a role with `costings`. A role without it can neither see the entry nor load the URL.
- [ ] Saving writes `service_prices` and the two keys, records one Audit Log entry with before and after, and survives a reload.
- [ ] The save route rejects a negative MSRP, an unknown key, `freeVisits` > 10 and `freeWindowDays` > 365, each with a 400 naming the field.
- [ ] A services-only save does not trigger the storefront price sync (asserted by a test spying on `syncAllAutoGeneratedProductPrices`).
- [ ] The Appointments settings sheet shows the live fee and rule and links to the page.
- [ ] The page works at 375 px width with no horizontal scroll (`components/settings/settings-mobile.check.ts`).

## Notes

`site_settings` is publicly readable (`20260308000000_create_site_settings.sql`). The two policy integers are not secret, since slice 10 prints them on the website. The prices stay in an RLS-locked table because they sit beside cost.
